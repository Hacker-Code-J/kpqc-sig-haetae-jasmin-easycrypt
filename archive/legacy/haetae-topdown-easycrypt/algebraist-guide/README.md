# HAETAE-2 Verification Guide for Algebraists

This folder contains an English LaTeX guide that lets pure algebraists and
algebraic geometers independently read the formal verification work in
`haetae-topdown-easycrypt`. The existing `../latex/` contains weekly research
and development records, and `../theory-guide/` is a detailed proof-status
report for mathematicians and cryptographic theorists. This guide focuses on
translation between the following three layers rather than repeating those
two documents.

Mathematical terminology uses standard English terms such as ring, quotient
ring, and commutative diagram.

1. HAETAE-2's mathematical objects, described over quotient rings and free modules;
2. maps representing those objects as canonical byte strings, prefixes, and
   memory regions;
3. reading actual Jasmin procedures and EasyCrypt Hoare/pRHL theorems as
   refinements of finite state machines.

## Build

For the English guide in this archived source tree, run from the current
repository root:

```sh
cd archive/legacy/haetae-topdown-easycrypt/algebraist-guide
latexmk -xelatex -interaction=nonstopmode -halt-on-error main.tex
```

The required tools are XeLaTeX, `latexmk`, and BibTeX. The English typesetting
uses TeX Gyre Pagella, TeX Gyre Heros, Latin Modern Mono, and TeX Gyre Pagella Math.
The document uses `\bibliographystyle{plain}` and `\bibliography{references}`;
`latexmk` runs BibTeX as needed. A successful build produces `main.pdf`.
Inspect the final log for undefined references/citations as well as LaTeX errors.

The original complete development tree used these historical commands, run
from that tree's repository root:

```sh
sh haetae-topdown-easycrypt/algebraist-guide/build.sh
./haetae-topdown-easycrypt/scripts/verify-all.sh
```

Those paths require a restored complete historical tree; they are not executable
entry points at the current repository root. The historical build script also
required `rg` and failed on unresolved references/citations or LaTeX errors.
Its proof-verification command checked EasyCrypt separately.

A successful PDF build of this guide does not replace successful EasyCrypt
proof checking. Conversely, historical `verify-all.sh` did not automatically
build this guide. When updating documentation and the historical proof baseline
together, run and verify both workflows in the appropriate complete tree.

## Updating the status

1. Update and verify `../CLAIM_LEDGER.md` and the actual `.ec` theorems first.
2. Update the date, target counts, and current gate in `status.tex`.
3. Update the status tables in Sections 4--7 together with the theorem index in
   Section 8.
4. Run both `build.sh` and `../scripts/verify-all.sh`.

`PROVED` means that the named theorem freshly compiles under the stated
premises. It does not automatically extend to a parent theorem, termination,
distributional equality, or complete API security.
