## Zero-HBZ prepare bridge

`Mode2RansAllSixBudget.zero_hbz_get32` expands the actual four-byte
`BArray8192.get32` load over an array initialized bytewise with `W8.zero` and
proves `W32.zero`. From that concrete load,
`zero_hbz_canonical` establishes the mode-2 coefficient range and
`prepared_zero_hbz_is_all_six` derives symbol 6 at every index below 1024.
`actual_prepare_zero_hbz_all_six` applies this result to the actual
`HbzFullEncodeTarget.M._encode_hb_z1_prepare` return, including `bad=0` and
the prepared-symbol tail frame. The all-six array is therefore generated by
the actual prepare call; it is not an assumed prepared witness.

## Coarse capacity argument

The literal table lemmas prove `hbz_freq 6 = 398` and
`hbz_xmax 6 = 2097152 * 398 = 834666496`.
`symbol6_div256_below_xmax` and `symbol6_normalization_len_le1` show that a
state below `2^31` can emit at most one normalization byte for symbol 6.
The pure encoder calculations give:

```text
8388608 -> 21582496 -> 55528910 -> 142868116 -> 367580518
```

so the first four steps emit zero bytes. `all_six_normalization_budget`
combines those four steps with the per-step bound and proves at most 1020
normalization bytes for 1024 symbols. `all_six_trace_fits_mode2` adds the four
serialized state bytes and proves total trace size in `[4,1024]`. No exact
174-byte normalization count is used as formal evidence.

## What the witness proves

The actual rANS witness opens `RansEncodeTarget.M._rans_encode` on the
canonical all-6 stream and proves:

- the encoder returns `bad = 0`;
- the returned offset satisfies `0 <= off <= 1020`;
- the returned size satisfies `4 <= 1024 - off <= 1024`;
- the returned suffix is exactly `mode2_trace_bytes all_six_symbols`;
- the initial prefix is preserved by `prefix_frame`.

The focused HBZ lift then proves the same all-6 trace bytes at the actual
`_encode_hb_z1_full` / `_decode_hb_z1_full` boundary, and the production
wrapper harness exposes the same fixed-input success branch.

## Failure cause

The failure branch is still explicit. `actual_rans_encode_failure_trace_cause`
states that a nonzero encoder `bad` implies the trace length is greater than
1020. This implication is retained from the actual `off < 4` guard through
the existing encoder outer/inner invariants. The pure all-six upper bound
contradicts that implication, leaving `bad=0`. This is a Hoare
partial-correctness consequence of
`actual_rans_encode_trace_closure_strong`; it is not a total or probabilistic
termination statement.

## Actual and production surfaces

`actual_rans_encode_all_six_success` directly targets
`RansEncodeTarget.M._rans_encode`. Its precondition contains only exact array
bindings, the literal mode-2 table, count 1024, and `all_six_prefix`; success,
buffer fit, returned offset, trace size, and exact output are postconditions.

`actual_encode_hb_z1_full_zero_success` directly targets
`HbzFullEncodeTarget.M._encode_hb_z1_full` with `hp=zero_hbz` and
`(count,mhb,offset)=(1024,13,6)`. It internally derives canonicality, actual

the output tail frame. `signature_pack_hbz_zero_success_mode2` formally lifts
that result to `SignaturePackMode2Target.M._encode_hb_z1_full` through the
compiled exact equivalence.

The focused and production zero-round-trip corollaries additionally prove
`decoder_ran=true`, decoder `bad=0`, the zero coefficient prefix, and both
coefficient and encoded tail frames without assuming encoder success.
