# Week 13 report — actual encoder/copy/decoder core inverse

## Decision

**GO-CORE.** `OBL-RANS-CORE-INVERSE` is now **PROVED as
success-conditioned Hoare partial correctness**. The compiled theorem directly
composes the actual extracted encoder, suffix-copy helper, and decoder through
the existing unary harness. Encoder success is not a precondition.

## Fresh-compiled theorem

The final theorem is:

```easycrypt
lemma actual_rans_encode_copy_decode_inverse
    (enc_initial copied_initial decoded_initial : BArray2048.t)
    (encoder_state_initial : BArray16.t)
    (decoder_state_initial : BArray24.t)
    (expected_symbols : BArray2048.t) :
  hoare [Mode2RansActualHarness.run :
    arg = (enc_initial, copied_initial, decoded_initial,
           encoder_state_initial, decoder_state_initial,
           expected_symbols) /\
    mode2_hbz_symbol_stream expected_symbols
    ==>
    encoder_failure_post \/ encoder_success_post].
```

The source expands both posts instead of using these schematic names. The
failure branch states `encoder_bad <> 0`, `decoder_ran=false`, initialized
decoder status, and equality of the returned decoded array/state with their
initial values. The success branch states:

- `encoder_bad=0` and `decoder_ran=true`;
- decoder input fields are exactly `(1024,encoded_size,13)`;
- decoder `bad=0` and `off=encoded_size`;
- all 1024 decoded symbols equal the actual encoder input symbols;
- decoded indices `[1024,2048)` equal the initial decoded array;
- `actual_core_success_result` holds;
- the actual encoder suffix still matches the exact trace and its lower prefix
  retains the initial encoder bytes.

The theorem directly targets `Mode2RansActualHarness.run`. That harness directly
calls, in order:

1. `RansEncodeTarget.M._rans_encode`;
2. `HbzFullEncodeTarget.M.__copy_encoded_suffix` on actual encoder success;
3. `RansDecodeTarget.M._rans_decode` after configuring its state.

This is a direct composition theorem over three actual extracted procedures,
not a production full-HBZ wrapper theorem.

## New bridge theorems

`Mode2RansCoreCompositionBridge.ec` fresh-compiles the following interfaces:

- `copied_suffix_is_exact_trace`: encoder `segment_matches` plus actual copy
  `slice_eq` yields copied `segment_matches` at offset zero;
- `trace_bytes_trace_segment_nth`: decoder cursor/segment indexing agrees with
  the global trace list;
- `segment_matches_implies_exact_decoder_segment_input`: the copied global
  segment supplies every Week 12 pointwise decoder byte read;
- `segment_matches_implies_decoder_word_reads`: W64-form read adapter;
- `actual_decoder_input_from_copied_trace`: exact trace, state fields, bounds,
  and canonical stream construct the decoder theorem's full input predicate;
- `configured_decoder_state_fields` and
  `actual_decoder_input_from_configured_trace`: the actual three state stores
  establish `(count,size,m)=(1024,size,13)`;
- `encoder_success_size_word_bridge`: actual success bounds make the harness's
  W64 subtraction exactly equal the integer trace size without wraparound;
- `core_composition_preconditions_satisfiable`: canonical-stream precondition
  witness.

The decoder's pointwise read relation is not a theorem precondition and no
arbitrary buffer witness is used.

## Failure branch and partial-correctness boundary

The proof branches on the actual encoder result. It does not require or infer
that the encoder succeeds. If the encoder returns nonzero `bad`, the harness
does not execute the actual copy or decoder and retains its initialized output
semantics. If it returns zero, the semantic round trip follows.

The theorem remains Hoare partial correctness. It does not prove:

- termination/losslessness of `_rans_encode` or `_rans_decode`;
- reachability of the encoder-success branch;
- an all-6 actual success witness;
- the production full-HBZ wrapper inverse;
- malformed-input rejection, canonical parsing, or complete signature codec;
- any encoding, Sign/Verify, or EUF-CMA zero-loss statement.

`OBL-RANS-ACTUAL-SUCCESS-WITNESS` and
`OBL-SIG-HBZ-ENCODE-DECODE` therefore remain `PARTIAL`.

## Failed approaches

- Re-inlining all three generated procedures was rejected because the encoder
  and decoder semantic refinements already compile and the remaining issue was
  premise transport, not loop semantics.
- Adding copied trace or decoder byte-read equality as a harness precondition
  was rejected as circular.
- Replacing the copied buffer with a constructed witness was rejected because
  it would sever the actual copy-helper path.
- Treating W64 subtraction as integer subtraction without bounds was rejected;
  the proof instead derives unsigned order and no-wrap from the actual encoder
  success postcondition.

## Non-vacuity

The final theorem's precondition is satisfiable by a canonical all-zero symbol
array. This establishes only precondition consistency. Because the conclusion
is a failure/success disjunction, it does not establish success-branch
reachability or termination.
