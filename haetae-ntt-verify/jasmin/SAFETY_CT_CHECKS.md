# Safety and Constant-Time Checks for the Jasmin NTT

This directory contains the Jasmin source for the scalar HAETAE NTT artifact:

- `hpoly.jazz`: exported wrappers and security annotations.
- `poly.jinc`: NTT, inverse NTT, and base-multiplication kernels.
- `reduce.jinc`: Montgomery reduction and field multiplication helpers.
- `params.jinc` and `zetas.jinc`: HAETAE parameters and twiddle tables.

Run the commands below from the repository root, not from this `jasmin/`
directory.  The checked entry point is:

```sh
jasmin/hpoly.jazz
```

## Toolchain

The paper artifact was checked with:

```sh
jasminc -version
```

Expected version for the recorded logs:

```text
Jasmin Compiler 2026.03.0
```

In this Jasmin release, safety checking is exposed through `jasminc
-checksafety`.  Constant-time and speculative constant-time checking are exposed
through the companion `jasmin-ct` executable from the same Jasmin toolchain.

## Safety Check

Run:

```sh
jasminc -checksafety -o hpoly-safe.s jasmin/hpoly.jazz
```

Expected result:

```text
*** No Safety Violation
```

for each exported routine:

- `poly_ntt_jazz`
- `poly_invntt_jazz`
- `poly_basemul_jazz`

The safety check proves defined execution under the exported function
preconditions.  For this artifact, that means the caller must pass valid and
properly aligned 256-word `u32` polynomial regions.  The typed pointers give the
checker the array shape and index discipline, but they do not by themselves
prove that an arbitrary caller pointer is valid.

The important source-level obligations are:

- polynomial accesses stay inside the `u32[HAETAE_N]` regions;
- twiddle-table accesses stay inside the declared 256-entry tables;
- mutable output pointers are used only where mutation is allowed;
- word-level arithmetic, casts, shifts, and helper calls stay within the Jasmin
  semantics.

## Regular Constant-Time Check

Run:

```sh
jasmin-ct jasmin/hpoly.jazz
```

Expected result:

the command should produce no diagnostic output and exit with status 0.

The exported wrappers in `hpoly.jazz` carry `#[ct = ...]` annotations.  The CT
checker uses these annotations to ensure that values derived from polynomial
coefficients may flow through arithmetic and stores, but not into observable
control flow or addressing.

For this artifact, the intended CT invariant is:

- loop guards are public;
- branch conditions are public;
- array indices and memory addresses are public;
- table lookups are indexed by public counters and public stage constants;
- coefficient values and arithmetic values derived from coefficients remain
  secret.

## Speculative Constant-Time Check

Run:

```sh
jasmin-ct --speculative jasmin/hpoly.jazz
```

Expected result: the command exits with status 0 and prints the inferred SCT
types for the checked routines.

The exported wrappers use `#[sct = ...]` annotations and call:

```jasmin
_ = #init_msf();
```

In the generated x86-64 assembly, this creates an entry `lfence` for each
exported wrapper.  The SCT claim is relative to the Jasmin SCT checker model:
the wrapper treats incoming pointer bases as transient at the ABI boundary, then
establishes a public addressing boundary before calling the internal kernels.
Loaded coefficient values remain secret.

This does not claim coverage of every physical or microarchitectural leakage
channel.  It is a Jasmin SCT/Spectre-v1-style checker claim for this source.

## Assembly Regeneration Check

After the safety and CT checks pass, regenerate assembly and compare it with the
checked assembly file:

```sh
jasminc jasmin/hpoly.jazz -o /tmp/hpoly-after.s
sha256sum hpoly.s /tmp/hpoly-after.s
diff -u hpoly.s /tmp/hpoly-after.s
```

Expected result:

- `jasminc` exits with status 0;
- the two SHA-256 hashes match;
- `diff` prints no output.

This step matters because the paper's source-to-assembly claim is about the
submitted `hpoly.s`.  If `hpoly.s` is hand-edited or generated by a different
compiler version, the checker logs must be regenerated and the assembly must be
compared again.

## Capturing Logs

To refresh the paper-style reproducibility logs, run:

```sh
jasminc -version > paper/logs/jasminc-version.log
git rev-parse --short HEAD > paper/logs/git-revision.log
jasminc -checksafety -o /tmp/hpoly-safe.s jasmin/hpoly.jazz > paper/logs/jasmin-checksafety.log 2>&1
jasmin-ct jasmin/hpoly.jazz > paper/logs/jasmin-ct.log 2>&1
jasmin-ct --speculative jasmin/hpoly.jazz > paper/logs/jasmin-ct-speculative.log 2>&1
jasminc jasmin/hpoly.jazz -o /tmp/hpoly-after.s > paper/logs/jasmin-compile.log 2>&1
sha256sum hpoly.s /tmp/hpoly-after.s > paper/logs/assembly-sha256.log
diff -u hpoly.s /tmp/hpoly-after.s > paper/logs/assembly-diff.log
```

The CT log may be empty when the check succeeds.  An empty
`assembly-diff.log` is also expected when the regenerated assembly matches.

## When to Rerun the Checks

Rerun all safety, CT, SCT, and assembly-comparison commands after changing any
of the following files:

- `jasmin/hpoly.jazz`
- `jasmin/poly.jinc`
- `jasmin/reduce.jinc`
- `jasmin/params.jinc`
- `jasmin/zetas.jinc`
- `hpoly.s`

Also rerun the checks after changing the Jasmin compiler version or target
compiler options.

In addition to rerunning the commands, manually review the leakage argument if a
change introduces any of the following:

- raw memory operations;
- new exported wrappers;
- changed `ct` or `sct` annotations;
- data-dependent branches or loop bounds;
- table indexing by coefficient-derived values;
- declassification.

## Interpretation

A successful run supports the narrow artifact claim:

1. `jasminc -checksafety` proves source-level safety under typed pointer
   preconditions.
2. `jasmin-ct` proves the regular branch/address constant-time property in the
   Jasmin leakage model.
3. `jasmin-ct --speculative` proves the Jasmin SCT checker property for the
   annotated exported wrappers.
4. Assembly regeneration proves that the checked source corresponds to the
   submitted `hpoly.s`.

These checks complement functional correctness proofs.  They do not prove by
themselves that the NTT computes the mathematically intended transform, and they
do not prove full HAETAE signature security.
