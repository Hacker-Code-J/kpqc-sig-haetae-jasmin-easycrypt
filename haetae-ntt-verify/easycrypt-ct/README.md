# Full-Safe Constant-Time EasyCrypt Workspace

This directory is the EasyCrypt verification workspace for the current
full-safe constant-time Jasmin implementation in `../jasmin/hpoly.jazz`.

The checked Jasmin source is stage-specialized for `jasminc -checksafety` and
annotated for `jasmin-ct` / `jasmin-ct --speculative`.  Its EasyCrypt
extraction is therefore not syntactically identical to the original direct-loop
extraction used by `../easycrypt/RefJasminNTT.ec`: the forward and inverse NTT
cores are decomposed into stage helper procedures such as
`_poly_ntt_stage_128` and `_poly_invntt_stage_1`.

## Files

- `Hpoly_extract.ec`: generated from `../jasmin/hpoly.jazz`.
- `Array256.ec`, `BArray1024.ec`, `WArray1024.ec`: array theories generated by
  `jasmin2ec`.
- `NTT_Fq.ec`, `NTTFullSpec.ec`, `NTTFullAlgebra.ec`: copied from the existing
  functional correctness stack.
- `FunctionalSupport.ec`: a small top-level support check that imports the
  reusable algebra stack and the regenerated extraction.
- `Hpoly_loop.ec`: proof-only direct-loop EasyCrypt model using the same
  constants and `__fqmul` as the CT extraction.
- `RefJasminNTTLoop.ec`: the existing direct-loop functional correctness proof
  retargeted to `Hpoly_loop.ec`.
- `CTLoopEquiv.ec`: machine-checked pRHL bridge proving the helperized CT
  extraction equivalent to the proof-only direct-loop model for forward NTT,
  inverse NTT, and public wrappers.
- `NTTEndToEnd.ec`: final end-to-end correctness theorems for
  `Hpoly_extract.M.poly_ntt_jazz` and `Hpoly_extract.M.poly_invntt_jazz`.
- `RefJasminNTT.ec`: the old copied proof target is kept intentionally as a
  historical boundary for the original direct-loop extraction shape.

## Commands

Regenerate the extraction:

```sh
cd easycrypt-ct
./scripts/regenerate-extract.sh
```

Compile the extraction and reusable functional-correctness support theories:

```sh
cd easycrypt-ct
./scripts/check-functional-support.sh
```

Check the full extracted-Jasmin functional correctness proof:

```sh
cd easycrypt-ct
./scripts/check-full-functional-correctness.sh
```

The verification scripts may also be launched from the repository root, for
example `./easycrypt-ct/scripts/check-full-functional-correctness.sh`; they
enter `easycrypt-ct` internally.  Each run writes a transcript under
`easycrypt-ct/logs/`, for example
`logs/full-functional-correctness.run.log`, plus per-target EasyCrypt logs
such as `logs/RefJasminNTTLoop.compile.log`.

The full check compiles every current EasyCrypt source used by the full-safe
constant-time proof bundle, in dependency order, with `-no-eco`:

- generated support theories: `Array256.ec`, `BArray1024.ec`,
  `WArray1024.ec`, `Hpoly_extract.ec`
- arithmetic and algebra theories: `Fastexp.ec`, `Montgomery.ec`, `GFq.ec`,
  `Rq.ec`, `Fq.ec`, `NTT_Fq.ec`, `NTTFullSpec.ec`, `NTTFullAlgebra.ec`
- CT proof theories: `FunctionalSupport.ec`, `Hpoly_loop.ec`,
  `RefJasminNTTLoop.ec`, `CTLoopEquiv.ec`, `NTTEndToEnd.ec`

It then scans all current checked targets for `admit` and `abort`, and checks
that EasyCrypt `axiom` declarations are confined to the expected foundational
boundary files `GFq.ec` and `Montgomery.ec`.  The old `RefJasminNTT.ec` file is
not part of the full check because it is preserved to show the pre-CT
direct-loop proof shape.  All check scripts use `-no-eco` so stale EasyCrypt
cache files cannot mask the result.
